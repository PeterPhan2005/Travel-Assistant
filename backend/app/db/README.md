# Server schema decisions

T030 defines mappings and migrations only. It does not create an engine,
session, repository, endpoint, seed importer, or application startup hook.

## Identifiers

- User-owned server entities (`users`, preferences, trips, itineraries, and
  itinerary items) use UUID primary keys generated by application-side
  SQLAlchemy defaults.
- Curated entities use bounded stable text identifiers. This preserves IDs such
  as `hcmc-poi-central-post-office` for deterministic T031 upserts without
  coupling server records to Room's storage layout.
- A user maps to exactly one nonblank, unique Firebase UID. No Firebase email,
  profile, password, credential, or token is stored.

## Preferences

Preferences are one versioned, non-null JSONB document per owner. JSONB keeps
the T030 schema minimal while the exact preference taxonomy remains undefined;
`schema_version` gives later synchronization an explicit contract boundary.
The database supplies an empty-object default and preserves update timestamps.

## Spatial storage

POI location is the canonical `GEOGRAPHY(POINT, 4326)` value with a GiST index.
Geography is deliberate because later nearby and travel-distance queries are
earth-distance operations across both HCMC and Bangkok. No user coordinate or
location-request history is represented in the schema.

## Ownership and deletion

- Deleting a user cascades to their preferences, trips, and itineraries.
- `(trip_id, user_id)` is a composite foreign key, preventing an itinerary from
  attaching to another user's trip. A trip referenced by an itinerary is
  restricted from deletion until the itinerary is detached; this preserves the
  independently retained itinerary.
- Deleting an itinerary cascades to its ordered items.
- Deleting curated POI content sets an itinerary item's optional POI reference
  to null, preserving its fallback title and other user plan context.
- POI-owned source links, menu items, and narrations cascade when that POI is
  deleted. Source deletion is restricted while retained curated records refer
  to it, so provenance cannot disappear silently.

Menus are represented by POI-owned `menu_items`; no empty menu aggregate or CMS
workflow is introduced.
